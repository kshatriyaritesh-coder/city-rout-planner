City Route Planner

Product Requirements Document (PRD) · Version 1.0

1. Overview

The City Route Planner is a web application for finding the shortest route between major Indian cities. It combines graph-based route calculation with live map visualization and supports multiple travel modes.

2. Problem Statement

Users often need quick route information between cities for travel, operations planning, and trip estimation. A simple and focused route planner helps them understand the best path without needing complex enterprise tools.

3. Product Goal

To provide a simple, fast, and visually clear route-planning experience for a defined set of cities using a lightweight weighted graph and map-based interface.

4. Target Users

Travelers, logistics planners, demo users, and general users who need route distance and path estimation between cities.

5. Core Use Cases

  • Select source and destination cities.
  • Choose travel mode such as driving, walking, train, or flight.
  • View the shortest path and total distance.
  • Review route alternatives for driving.
  • See the route highlighted on an interactive map.
  • Receive clear feedback when the route is unavailable.

6. Functional Requirements

  • The app must load a list of available cities from the backend.
  • The backend must compute the shortest path between two cities using a weighted graph.
  • The UI must allow city and travel-mode selection.
  • The app must display a route path like Delhi → Jaipur → Ahmedabad.
  • The selected route must be visible on a map with markers and polylines.
  • When no valid route exists, the app must show a clear no-route message.
  • When external APIs are unavailable, the app must show a graceful service error.

7. Non-Functional Requirements

  • Fast response for small in-memory city networks.
  • Responsive and intuitive interface.
  • Graceful fallback when external map services fail.
  • Maintainable separation between backend graph logic and frontend presentation.
  • Accessible form controls and readable route feedback.

8. User Stories

  • As a traveler, I want to choose two cities and see the shortest route so I can estimate travel distance.
  • As a user, I want to compare driving alternatives so I can pick the most suitable route.
  • As a user, I want to view routes on a map so I can understand geography more clearly.
  • As a user, I want clear error messages so I know when a route is impossible or a service is unavailable.

9. Product Scope

In Scope: curated city graph, shortest-path search, map visualization, route alternatives, and basic mode handling.

Out of Scope for MVP: real-time traffic, exact railway schedules, flight scheduling, user accounts, bookmarks, and large-scale global road data.

10. Success Metrics

  • Users can successfully find a valid route between any two cities in the graph.
  • Route results render correctly on the map without manual refresh.
  • The user experience remains intuitive and easy to follow.

11. Acceptance Criteria

  • Given a valid source and destination, the app displays the route and total distance.
  • Given unreachable cities, the app displays a no-route response.
  • Given a valid route, the map centers and zooms to fit the active route.
  • Given invalid input, the backend returns a clear 400-style message.
  • For driving and walking modes, route geometry is rendered as a polyline on the map.

12. Technical Architecture

Frontend: React app with Leaflet and react-leaflet for map display.

Backend: Node.js and Express for API routes.

Routing engine: Weighted graph with shortest-path computation.

External services: OSRM for driving routes and Valhalla for walking route generation.

13. Risks and Constraints

  • External route APIs may be unavailable or rate-limited.
  • Train and flight modes are informational rather than schedule-accurate.
  • The route graph is a curated demo network, not production-grade road infrastructure data.

14. Proposed Next Enhancements

  • Add more cities and richer graph data.
  • Add ETA and travel-time estimates.
  • Add route history or saved trips.
  • Add real train and flight APIs.
  • Add traffic-aware route optimization and geo-accurate pathing.
